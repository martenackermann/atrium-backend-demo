# Conventions

Rules for everyone working in `atrium-backend-demo` (foundation and slices A1-A4).
When something here is unclear, follow the existing code in `src/common` and `src/infra`.

## 1. Layout

```
src/
  main.ts                    bootstrap (listen on PORT)
  app.module.ts              infrastructure + feature-module registry
  bootstrap/                 configureApp() (prefix, helmet, CORS, Swagger), OpenAPI builder
  config/                    zod env schema (env.schema.ts) + AppConfig (typed access)
  database/                  PrismaService (global), PrismaTx type, truncate, seed runner + registry
  common/                    cross-cutting libraries, no business logic
    http/                    problem+json, validation pipe, pagination, sort, OpenAPI helpers
    auth/                    JWT guard, @Public, @CurrentUser, TokenService, PasswordHasher
    authz/                   CASL AppAbility, AbilityFactory, @AbilityRules, @CheckAbility, assertCan
    workflow/                XState workflow engine (WorkflowService, defineWorkflow, workflowActions)
    logging/  throttle/      pino request logging + request id, /auth/* rate limit
  infra/                     IO modules: queue (pg-boss), mail (MJML+SMTP), storage (files), health
  modules/<m>/               feature modules: core, training, travel, assets, people, news, home
  generated/prisma/          Prisma client (generated, git-ignored)
prisma/schema/               schema.prisma (generator+datasource), system.prisma, <module>.prisma
prisma/migrations/           SQL migrations (generated by the foundation/QA owner only)
test/                        e2e tests (*.e2e-spec.ts) + support helpers
```

### Feature module layout

```
src/modules/<m>/
  <m>.module.ts              the Nest module (imports MailModule.forFeature, lists providers)
  README.md
  controllers/               <resource>.controller.ts   - HTTP only, no Prisma calls
  services/                  <resource>.service.ts      - business logic, Prisma access
  dto/                       <resource>.dto.ts          - zod schemas + createZodDto classes
  machines/                  <resource>.workflow.ts     - XState machine + defineWorkflow()
  abilities/                 <m>.abilities.ts           - @AbilityRules() provider
  jobs/                      <m>.jobs.ts                - @JobHandler() / @Cron() providers
  mail/                      <purpose>.mail.ts          - defineMailTemplate()
  seed/                      <m>.seed.ts                - export const <m>Seeder: Seeder
  **/*.spec.ts               unit tests next to the code
prisma/schema/<m>.prisma     this module's models
```

**Ownership rule:** a slice edits only `src/modules/<m>/**`, `prisma/schema/<m>.prisma` and
`test/e2e/<m>*.e2e-spec.ts`. Outside those it may only add **one line** to a documented
registry: the module import in `src/app.module.ts` (already present for all modules) and the
seeder list in `src/database/seed/seeders.ts`. Anything else goes through the foundation owner.

## 2. Naming

- Files kebab-case with a role suffix: `training-request.service.ts`, `create-training-request.dto.ts`.
- Classes PascalCase (`TrainingRequestService`), DTO classes end in `Dto`, query DTOs in `Query`.
- Prisma models PascalCase singular; map tables/columns to snake_case (`@@map("training_requests")`, `@map("created_at")`).
- Ids: `String @id @default(uuid(7)) @db.Uuid` (UUIDv7, generated by Prisma in the app).
- Routes: plural kebab-case nouns, `/api/v1/training-requests/:id`. Workflow actions: `POST /<resource>/:id/actions/:action`.
- Queue names `<module>.<job>` (`training.send-reminder`), mail templates `<module>.<purpose>` (`training.request-approved`), ability subjects = Prisma model names.

## 3. DTOs and validation (zod + nestjs-zod)

```ts
// dto/training-request.dto.ts
export const createTrainingRequestSchema = z.object({
  title: z.string().trim().min(3).max(200),
  startsOn: z.iso.date(),
});
export class CreateTrainingRequestDto extends createZodDto(createTrainingRequestSchema) {}

export const trainingRequestSchema = z.object({ id: z.uuid(), title: z.string(), status: z.string() });
export class TrainingRequestDto extends createZodDto(trainingRequestSchema) {}
```

- `@Body() dto: CreateXDto`, `@Query() query: ListXQuery`, `@Param('id', ParseUUIDPipe) id`.
  The global `AppValidationPipe` validates every zod DTO; failures become **422** problem+json.
- Responses: `@ZodResponse({ type: XDto })` (serialises through the schema and documents it) or
  `@ApiOkResponse({ type: XDto })`. Never return Prisma rows with secrets (password hashes...).
- Do not set `.meta({ id })` on a DTO's root schema (the class name is the OpenAPI schema name).
- Dates: `z.iso.date()` / `z.iso.datetime()` strings in DTOs; convert in the service.

## 4. Errors (RFC 9457 problem+json)

Every error leaves the API as `application/problem+json`:
`{ type, title, status, detail, instance, requestId, errors? }`. Types are
`https://atrium.example.com/problems/<slug>` (see `ProblemType`).

```ts
throw ProblemException.notFound('TrainingRequest', id); // 404
throw ProblemException.forbidden(); // 403
throw ProblemException.conflict('Already booked.'); // 409
throw ProblemException.validation({ startsOn: ['Must be in the future'] }); // 422 with field errors
throw ProblemException.invalidTransition('approve', 'draft'); // 409 invalid-transition
```

Field errors use dotted paths (`items.0.qty`); payload-level errors use `_root`. Prisma
`P2002` maps to 409, `P2025` to 404, anything unknown to a generic 500 (details only in logs).
Document error responses with `@ApiProblemResponses(404, 409, 422)`.

## 5. Lists: pagination and sorting

```ts
export const listTrainingRequestsSchema = paginationQuerySchema.extend({
  status: z.enum(['draft', 'submitted']).optional(),
  sort: sortParam({ allowed: ['createdAt', 'title', 'requester.lastName'], default: '-createdAt' }),
});
export class ListTrainingRequestsQuery extends createZodDto(listTrainingRequestsSchema) {}

// service
return paginate(
  query,
  (page) => this.prisma.trainingRequest.findMany({ where, orderBy: toPrismaOrderBy(query.sort), ...page }),
  () => this.prisma.trainingRequest.count({ where }),
);
// -> { data: T[], meta: { page, perPage, total, totalPages } }
```

`perPage` defaults to 20, max 100. `sort=a,-b`; fields outside the allowlist are a 422 on `sort`.
Response schema: `paginatedSchema(itemSchema)`.

## 6. Auth and authorization

- Every route requires `Authorization: Bearer <jwt>` unless decorated with `@Public()`.
- `@CurrentUser() user: AuthUser` (`{ id, email, roles }`); on public routes `@CurrentUser({ optional: true })`.
- Rules: one `@Injectable() @AbilityRules()` provider per module implementing
  `AbilityRulesContributor.define(user, { can, cannot })`; list it in the module's `providers`.
  Conditions are Prisma `where` objects, so the same rules filter queries:
  `where: { AND: [accessibleBy(ability).TrainingRequest, filters] }`.
- Type-level checks on routes: `@CheckAbility('read', 'TrainingRequest')`.
  Instance checks in services: `assertCan(ability, 'update', subject('TrainingRequest', row))`.
  Get the request's ability with `@CurrentAbility() ability: AppAbility`.
- Passwords: `PasswordHasher` (argon2id). Tokens: `TokenService.issue(user)`.

## 7. Workflows (XState v5 + WorkflowService)

A workflow = pure machine + persistence binding. The engine never runs actors; it resolves a
snapshot from the stored state, checks `snapshot.can(event)` and CASL, and applies the transition.

```ts
// machines/training-request.workflow.ts
export const trainingRequestMachine = setup({
  types: { context: {} as Ctx, events: {} as WorkflowEvent<'SUBMIT'> | WorkflowEvent<'DECLINE', { reason: string }> },
  guards: { isRequester: ({ context, event }) => event.actor.id === context.requesterId },
  actions: { ...workflowActions },
}).createMachine({
  initial: 'draft',
  states: {
    draft: { on: { SUBMIT: { guard: 'isRequester', target: 'submitted' } } },
    submitted: { entry: { type: 'notify', params: { kind: 'training.request-submitted', to: ['approver'] } } },
  },
});

export const trainingRequestWorkflow = defineWorkflow({
  name: 'training-request',
  subjectType: 'TrainingRequest',
  machine: trainingRequestMachine,
  actions: { submit: { event: 'SUBMIT' }, decline: { event: 'DECLINE', ability: 'decide', input: declineSchema } },
  entityId: (row) => row.id,
  toState: (row) => ({ value: row.status, context: { requesterId: row.requesterId } }),
  load: (tx, id) => tx.trainingRequest.findUnique({ where: { id } }),
  persist: async (tx, row, next, change) => {
    const { count } = await tx.trainingRequest.updateMany({
      where: { id: row.id, status: change.fromState }, // compare-and-set
      data: { status: next.value },
    });
    return count ? { ...row, status: next.value } : null; // null -> 409
  },
});
```

Controller endpoint (one per resource):

```ts
@Post(':id/actions/:action')
async act(@Param('id', ParseUUIDPipe) id: string, @Param('action') action: string, @Body() body: unknown,
          @CurrentUser() user: AuthUser, @CurrentAbility() ability: AppAbility) {
  const result = await this.workflows.apply(trainingRequestWorkflow, { id, action, actor: user, ability, input: body });
  return this.toDto(result.entity, user, ability);   // include workflows.view(...) -> { state, availableActions }
}
```

`apply()` runs in one Prisma transaction: load -> CASL check (403) -> input validation (422) ->
guard check (409 `invalid-transition`) -> persist (409 on concurrent change) -> audit entry ->
`workflow.notify` jobs for every `notify` action. Guards may read `event.actor` and context but
not `event.input` (availability is computed without input). See
`src/common/workflow/examples/toy-request.workflow.ts` and its spec for a complete example.

## 8. Jobs (pg-boss) and crons

```ts
@Injectable()
export class TrainingJobs {
  constructor(private readonly queue: QueueService) {}

  @JobHandler('training.send-reminder', { queue: { retryLimit: 3, retryDelay: 60 } })
  async sendReminder(data: { requestId: string }) {
    /* throw to retry */
  }

  @Cron('0 7 * * 1-5', { name: 'training.daily-reminders', timeZone: 'Europe/Berlin' })
  async enqueueReminders() {
    await this.queue.send('training.send-reminder', { requestId });
  }
}
```

- List the provider in the module's `providers`; QueueService discovers `@JobHandler` methods.
- Enqueue with `queue.send(name, data, { tx })` - pass `tx` inside a Prisma transaction so the
  job only exists if the transaction commits.
- Crons (`@nestjs/schedule`) only **enqueue** jobs; the work happens in the handler.
- Handlers must be idempotent (retries happen).

## 9. Mail

```ts
// mail/request-approved.mail.ts
export const requestApprovedMail = defineMailTemplate({
  name: 'training.request-approved',
  schema: z.object({ name: z.string(), url: z.url() }),
  subject: (d) => `Your training request was approved`,
  body: (d) => mjml`<mj-text>Hello ${d.name},</mj-text><mj-button href="${d.url}">Open</mj-button>`,
  preview: { name: 'Emma Employee', url: 'http://localhost:3000/training' },
});
// module: imports: [MailModule.forFeature([requestApprovedMail])]
// service: await this.mail.send(requestApprovedMail, { to: user.email, data }, { tx });
```

- Bodies are MJML fragments inside the shared layout (wordmark header, "Acme IT Services · demo" footer).
- Interpolate only through the `mjml` tag (escapes HTML); `raw()` for trusted markup.
- Mail is always sent through the `mail.send` queue (Mailpit in dev: http://localhost:8025).
- Preview every template at `GET /api/v1/dev/mail-preview/<name>` (uses `preview` data).

## 10. Files

- Validate uploads with `assertValidUpload(file, UploadPresets.documents)` (size, type, extension, magic bytes).
- `storage.save(buffer, { originalName, mimeType })` returns `{ key, size, mimeType, originalName, sha256 }`; persist the key.
- Never expose keys or paths; hand out `storage.createDownloadUrl(key, { fileName })`
  (HMAC-signed, 5 min default) served by `GET /api/v1/files/:token`.

## 11. Database and seeds

- Models live in `prisma/schema/<m>.prisma`; relations to foundation models are allowed.
- During development use `pnpm db:push` against your own database (see `_spec/WORKSPACE.md`).
  Migrations are generated only on `main` by the foundation/QA owner after merging slices.
- `pnpm db:reset` = truncate all tables + `db push` + seed (no `--force-reset`).
- Seeders are plain functions (no DI): `export const trainingSeeder: Seeder = { name: 'training', run: async ({ prisma, faker, now }) => {...} }`,
  registered with one line in `src/database/seed/seeders.ts`. Use the seeded `faker` and dates relative to `now`.
- Demo persona password is the literal `demo1234` (`DEMO_PASSWORD`), demo only.

## 12. Tests

- Unit tests: `*.spec.ts` next to the code, no database (`pnpm test:unit`).
- E2E tests: `test/e2e/<m>-*.e2e-spec.ts`, boot the real app against `atrium_test`
  (each slice uses its own `*_test` DB via `TEST_DATABASE_URL`). Tables are truncated before
  each file; files run sequentially.

```ts
let t: TestApp;
beforeAll(async () => { t = await createTestApp(); });
afterAll(async () => { await t?.close(); });

it('creates a request', async () => {
  const auth = await t.bearer({ id: user.id, roles: ['employee'] });
  await t.http().post('/api/v1/training-requests').set('Authorization', auth).send({...}).expect(201);
});
```

- `t.app.get(QueueService).spy(name).waitForJob(selector, 'completed')` waits for background jobs.
- Assert error shapes (`type`, `status`, `errors`) rather than messages.

## 13. Tooling

`pnpm lint` (ESLint flat config + Prettier check), `pnpm typecheck`, `pnpm test`, `pnpm build`,
`pnpm openapi:export` (commit the updated `openapi.json`; CI checks it). Path alias `@/` = `src/`.
Commits: conventional commits (`feat(training): ...`, `fix(core): ...`).

## 14. Decisions (foundation)

- NestJS **11** (not 12): `nestjs-zod` 5 supports Nest <= 11.
- TypeScript **6.0**: `typescript-eslint` does not support the native TS 7 compiler yet.
- Prisma **7.10** (latest stable; 8.0 is a release candidate) with the `prisma-client` generator
  (output `src/generated/prisma`, CommonJS) and the `@prisma/adapter-pg` driver adapter.
- `SMTP_HOST` defaults to `127.0.0.1`: nodemailer resolves host names through DNS, not the hosts file.
- The `/auth/*` rate limiter is the throttler named `default`, so standard `Retry-After` headers are sent.
- Test/DB resets truncate tables and run `prisma db push` instead of `--force-reset`
  (Prisma blocks force-resets from AI agents without explicit user consent).
